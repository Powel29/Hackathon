1. EXECUTIVE SUMMARY
1.1 Product Vision
SUVIDHA is a unified self-service kiosk platform that enables citizens to access civic utility services (Electricity, Gas, Water, Municipal) through an intuitive, multilingual, touch-based interface with Aadhaar-based authentication.
1.2 Problem Statement
Indian civic utility offices face:
•	Long queues and manual paperwork
•	Inconsistent service quality
•	Limited transparency in complaint resolution
•	Language barriers for non-English speakers
•	High administrative burden on staff
1.3 Solution Overview
A single integrated kiosk system that:
•	Supports multiple utility services
•	Provides self-service capabilities 24/7
•	Offers multilingual support
•	Ensures secure Aadhaar-based authentication
•	Enables real-time service tracking
1.4 Success Metrics
•	70% reduction in counter queue time
•	90%+ citizen satisfaction rate
•	50% reduction in staff workload
•	95%+ transaction success rate
•	Support for 3+ languages at launch

3. FUNCTIONAL REQUIREMENTS
3.1 Authentication System
FR-AUTH-001: Aadhaar-Based Login
Priority: P0 (Critical)
Description: User authentication using 12-digit Aadhaar number and OTP verification
Acceptance Criteria:
•	System validates Aadhaar format (12 digits, Verhoeff algorithm)
•	System sends OTP to Aadhaar-linked mobile number
•	OTP is valid for 5 minutes
•	Maximum 3 OTP verification attempts allowed
•	User can request new OTP after 30 seconds
•	System displays masked mobile number (******3456)
•	Failed attempts are logged for security
User Flow:
1. User selects language
2. User selects utility service
3. User enters 12-digit Aadhaar number
4. System validates Aadhaar format
5. System sends OTP to registered mobile
6. User enters 6-digit OTP
7. System verifies OTP
8. System creates/retrieves user profile
9. User redirected to dashboard
Error Handling:
•	Invalid Aadhaar: "Please enter a valid 12-digit Aadhaar number"
•	OTP expired: "OTP expired. Click 'Resend OTP'"
•	Wrong OTP: "Incorrect OTP. X attempts remaining"
•	Rate limit exceeded: "Too many attempts. Try after 1 hour"
________________________________________
FR-AUTH-002: New User Registration
Priority: P0 (Critical)
Description: Auto-registration for first-time Aadhaar users
Acceptance Criteria:
•	System checks if Aadhaar exists in database
•	For new users, system fetches name, DOB from mock Aadhaar database
•	System captures mobile number for new users
•	User profile created with minimal data
•	Consumer ID generated or linked based on utility type
Data Fields (Auto-populated):
•	Name (from Aadhaar)
•	Date of Birth (from Aadhaar)
•	Gender (from Aadhaar)
•	Address (from Aadhaar)
Data Fields (User Input):
•	Mobile number (10 digits, validated)
•	Email (optional)
•	Utility type selection
•	Consumer ID (if existing customer)
________________________________________
FR-AUTH-003: Session Management
Priority: P0 (Critical)
Description: Secure session handling for kiosk usage
Acceptance Criteria:
•	Session created on successful login
•	Session expires after 5 minutes of inactivity
•	Warning shown at 4 minutes: "Session expiring in 60 seconds"
•	Auto-logout on session expiry
•	All form data cleared on logout
•	Session data not persisted in browser storage
•	Each kiosk logs session activity

3.2 Bill Payment System
FR-BILL-001: View Bills
Priority: P0 (Critical)
Description: Display all bills for authenticated user
Acceptance Criteria:
•	Show all bills (paid and unpaid) for logged-in user
•	Display bill number, amount, due date, status
•	Sort bills by due date (oldest first)
•	Highlight overdue bills in red
•	Show payment history for paid bills
•	Support pagination if bills > 10
UI Requirements:
•	Large touch-friendly cards (minimum 100px height)
•	Color-coded status: Green (Paid), Red (Overdue), Orange (Pending)
•	Clear "Pay Now" button for unpaid bills
•	Icons for bill type (electricity, gas, water, municipal)
________________________________________
FR-BILL-002: Bill Payment
Priority: P0 (Critical)
Description: Process bill payments through integrated payment gateway
Acceptance Criteria:
•	User selects bill to pay
•	System displays bill summary (amount, due date, bill number)
•	User confirms payment
•	System initiates Razorpay payment
•	Payment methods supported: UPI, Cards, NetBanking
•	System verifies payment signature
•	System updates bill status to "PAID" on success
•	System generates digital receipt
•	Option to print receipt
Payment Flow:
1. User clicks "Pay Now" on bill
2. Bill summary displayed
3. User clicks "Proceed to Pay"
4. Razorpay payment modal opens
5. User completes payment
6. System verifies payment
7. Bill marked as paid
8. Receipt generated
9. Option to print/email receipt
Error Handling:
•	Payment failed: Show error, allow retry
•	Network error: Queue transaction for later processing
•	Timeout: Verify payment status before retrying

3.7 Security & Compliance
FR-SEC-001: Data Encryption
Priority: P0 (Critical)
Description: Secure handling of sensitive user data
Acceptance Criteria:
•	Aadhaar numbers hashed (SHA-256) before storage
•	OTPs encrypted in database
•	Payment data transmitted via HTTPS/TLS
•	Session tokens encrypted
•	No plain text storage of sensitive data
•	Audit logs for all data access
________________________________________
FR-SEC-002: Session Security
Priority: P0 (Critical)
Description: Prevent unauthorized access and data leakage
Acceptance Criteria:
•	Auto-logout after 5 minutes inactivity
•	Clear all form data on logout
•	No data cached in browser
•	Session ID rotated on each login
•	Rate limiting on API endpoints (100 requests/15 min)
•	CAPTCHA after 3 failed login attempts
________________________________________
FR-SEC-003: DPDP Act Compliance
Priority: P0 (Critical)
Description: Comply with Digital Personal Data Protection Act
Acceptance Criteria:
•	User consent collected for data processing
•	Privacy policy displayed before registration
•	Data retention policy: Delete inactive users after 2 years
•	Right to erasure: Users can request data deletion
•	Data minimization: Collect only necessary information
•	Audit logs maintained for 6 months

## **6. USER INTERFACE DESIGN**

### **6.1 Design Principles**

1. **Large Touch Targets**: Minimum 80x80px for all buttons
2. **High Contrast**: Text easily readable from 2 feet away
3. **Minimal Text**: Use icons + short labels
4. **Clear Hierarchy**: Primary action always prominent
5. **Progress Indicators**: Show steps in multi-step flows
6. **Immediate Feedback**: Loading states, success/error messages
7. **Forgiving Design**: Allow back/cancel at any step

- Primary Blue: #0066CC (Trust, Government)
